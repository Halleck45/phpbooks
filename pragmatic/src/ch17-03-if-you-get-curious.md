# If You Get Curious About What's Underneath

If you opened every "Under the hood" box in this book, you already know more about the engine than this book asked you to learn. You have seen Fibers make a WebSocket server possible, attributes and reflection generate a whole API from one class, and a type system solid enough for static analysis to catch bugs before a single test runs. None of it was framed as a language lesson. It was framed as "here is why the convenience you just used works."

**If that pattern started to interest you for its own sake, this book was quietly built to lead you here.**

*The PHP Book* picks up at that point: variables, types, control flow, classes, and the engine's own error model, taught properly rather than reverse-engineered from a framework's behavior. It assumes what you brought here, coding experience elsewhere, and points it at the language instead of at one framework's conventions.

You do not need it to keep shipping. Every feature in this book works today, in production, without opening it once. It is there for the day "just ship it" turns into "wait, how does this work?" If you have read this far, that day may come sooner than you expected.
