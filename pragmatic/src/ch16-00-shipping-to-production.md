# Shipping to Production

A feature isn't shipped until it's live, and "live" means someone, possibly you, is now responsible for it staying up, staying patched, and surviving the traffic it gets. This chapter isn't about writing more code; it's about the last mile between "works locally" and "a real client is using this."

- [Laravel: Forge and Vapor ($)](ch16-01-laravel-forge-vapor.md) covers Laravel's own official deployment products.
- [Cloud Hosting: AWS, GCP, and Azure the Pragmatic Way](ch16-02-cloud-hosting-aws-gcp-azure.md) covers deploying when the client already has a cloud contract.
- [Platform.sh ($): One Deploy Story for Several Frameworks](ch16-03-platform-sh.md) covers a managed PaaS that isn't tied to one framework.
- [WordPress: Managed Hosting Done Right (Kinsta, WP Engine $)](ch16-04-wordpress-managed-hosting.md) covers hosting built specifically around WordPress's needs.
- [Nextcloud: All-in-One Docker Deployment](ch16-05-nextcloud-aio-docker.md) covers the officially recommended, self-hosted deployment path.
