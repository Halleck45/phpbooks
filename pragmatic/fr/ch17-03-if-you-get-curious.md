# Si vous devenez curieux de ce qu'il y a dessous

Si vous avez ouvert chaque encadré « Sous le capot » de ce livre, vous en savez déjà plus sur le moteur que ce livre ne vous demandait d'apprendre. Vous avez vu des Fibers rendre possible un serveur WebSocket, des attributs et de la réflexion engendrer une API entière à partir d'une classe, et un système de types assez solide pour que l'analyse statique attrape des bugs avant le premier test. Rien de tout cela n'était présenté comme une leçon de langage. C'était présenté comme « voilà pourquoi la facilité que vous venez d'utiliser fonctionne ».

**Si ce motif a commencé à vous intéresser pour lui-même, ce livre a été discrètement construit pour vous mener ici.**

*The PHP Book* reprend à ce point précis : variables, types, structures de contrôle, classes, et le modèle d'erreurs du moteur lui-même, enseignés pour de bon plutôt que déduits du comportement d'un framework. Il suppose ce que vous avez apporté ici, de l'expérience de code ailleurs, et la tourne vers le langage plutôt que vers les conventions d'un framework.

Vous n'en avez pas besoin pour continuer à livrer. Chaque fonctionnalité de ce livre marche aujourd'hui, en production, sans l'ouvrir une seule fois. Il est là pour le jour où « livre, c'est tout » devient « attendez, comment ça marche ? ». Si vous avez lu jusqu'ici, ce jour viendra peut-être plus tôt que prévu.
